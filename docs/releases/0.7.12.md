# 0.7.12

## Changes

- Remove the unread inbox page, navigation, dedicated queries, and assets. Subscription reading links
  and the article page's default return link now open the recent reader.
- Use smaller news titles and excerpts, with three columns at 1440px and four at 1920px.
  Taller image areas show the complete source image; narrow screens retain a single column.
- Keep saved articles, bookmarks, read state, and reader filters. No schema or configuration migration.
- Correct the bookmark interaction tests to load the script that owns those interactions.

## Validation

- `./gradlew test bootJar`: 654 tests passed.
- `node --test src/test/js/*.test.cjs`: 27 tests passed.
- Browser checks at 390, 768, 1024, 1440, and 1920px: no horizontal overflow or clipped actions.
- List mode, image loading, and complete-image scaling checked in the browser.

## NAS deployment

- Build `fetch-news:0.7.12-amd64` for `linux/amd64`, transfer it to NAS, and load it into Docker.
- Stop `fetch-news` and archive `/volume1/docker/fetch-news` before switching containers.
- Preserve the existing port `14001:8080`, data mount, environment overrides, logging, and restart policy.
- Retain the stopped 0.7.11 container and its image for rollback.
- Verify authenticated reader, admin, bookmarks, search, and briefing requests; check the displayed version
  and the exact reader stylesheet checksum. The removed inbox and stylesheet must return 404.

The switch briefly interrupts requests. Old `/reader/unread` bookmarks now return 404; `/reader` is the
replacement entry point. No database restoration is needed for an application rollback.

## Rollback

The deployment writes a protected `rollback.sh` beside its data archive in
`/volume1/docker/fetch-news-releases/`. It stops and removes only the new container, restores the retained
0.7.11 container's name and restart policy, and starts it against the existing data directory.
