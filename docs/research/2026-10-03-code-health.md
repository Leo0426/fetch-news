# 代码与运行策略审查（2026-10-03）

本轮以个人自用为目标：可靠收集新闻、减少重复工作、提升阅读效率、控制本地 AI 成本。基于 `2b267c7`；`git pull --ff-only` 确认与 `origin/main` 一致。保留已有阅读器页面改动及 ADR 0001。

## 本轮实施范围

| 问题 | 原有行为与影响 | 调整策略 |
| --- | --- | --- |
| 请求缓存碎片化 | `format`、`limit` 各自触发抓取；`limit=1` 还会只保存一条新闻 | 缓存完整 Feed，统一抓取与入库，输出层裁剪；离线响应遵守同一参数规则 |
| 配置变更未进入缓存身份 | 修改 RSS `feedUrl` 后仍可能读到旧源 | 缓存键包含来源、feedUrl 与 TTL 配置 |
| 并发缓存击穿 | `getIfPresent → load → put` 不是原子操作；慢请求消耗缓存有效期 | 相同键只加载一次，有效期从加载完成计算，失败不缓存 |
| 空源误报健康 | 空 Feed 先入成功日志、进入缓存，再由控制器报错 | 在统一抓取层拒绝空 Feed，记录失败，允许下一次请求立即恢复 |
| 调度任务重叠 | 同源慢于 60 秒时每个 tick 都能提交新任务 | 调度与手动刷新共享按路径去重，完成或失败后释放；不同源仍可并发 |
| 飞书进度提前推进 | HTTP/业务失败也更新游标；发送期间新到新闻可能被跳过 | 明确检查业务成功码；仅整批确认后更新进度，保留查询时的时间上界 |

以上调整已通过回归测试。飞书同时增加按路由/类别的发送防重，避免长批次跨过下一次 tick 时重发。以上策略不承诺跨进程任务去重或投递恰好一次。

## 架构判断

保留现有单体、显式路由注册和 SQLite。`FeedFetcher` 作为抓取、入库、日志的统一入口有实际价值；它应保存来源的完整结果，HTTP 输出参数留在控制器。`CacheService` 应隐藏并发和过期处理，调用方只提供键、TTL 与加载函数。无需增加通用 Repository/Service 转发层，也无需引入消息中间件。

后续架构候选按收益排序：

1. **正文获取与摘要入口统一**：`ArticleExtractor` 和 `ArticleSummarizer` 重复创建 HTTP 客户端、抓网页和抽正文；手动摘要传入空 description，未利用 `feed_items` 中已有正文。统一正文解析顺序为数据库正文/抽取缓存 → 原站，集中 HTTP 策略。收益是离线可摘要和减少重复抓取；需要兼顾已有 AI 抽取缓存的语义。
2. **本地 AI 并发控制与任务恢复**：`ArticleSummarizer` 的检查缓存、推理、保存之间存在竞态；调度与手动入口可重复处理同 URL。建立同 URL 合并、有限推理并发、明确的排队/失败状态。以单 URL 多入口并发测试、关闭重启后的状态恢复测试验证，不直接增加外部队列。
3. **存储事务与连接边界**：`FeedStore.saveItems` 的批量 upsert 和 FTS 刷新没有一个共同事务；单 Connection 的读方法未与写方法使用相同同步边界。WAL 不能替代应用层事务隔离。先做失败注入、查询计划和真实数据量基准，再选择串行连接或短生命周期读连接，避免无证据引入连接池。
4. **路由类别解析统一**：注册表类别以 `/hn/:feed` 为键，而调度/投递等处以 `/hn/top` 精确查找。应从实际 RouteMatch 得到类别，供别名、阅读器、即时推送、摘要推送共享；避免各处复制字符串匹配。
5. **轻量配置加源**：ADR 0001 已接受通用 CSS 选择器路由。继续遵守单个显式注册的 RouteHandler 和配置数据模型，不引入脚本执行、动态插件或浏览器抓取系统。

## 抓取和 AI 策略建议

- 先观测每源成功率、延迟、新增条数、连续失败数，再调整刷新间隔。当前代码不能证明统一缩短间隔能带来收益。
- 下一步实现 HTTP 条件请求、429/503 的 `Retry-After`、有上限的退避；将网络错误与解析错误区分。每源串行和不同源并发应分别约束。
- 内容获取成功后尽快入库供阅读与投递；摘要后台处理，单条失败不阻塞整个源。
- 对已有可用正文直接摘要；短正文优先确定性抽取，再决定是否需要额外 LLM 清洗，记录模型调用次数和耗时。模型与提示词版本应进入摘要缓存更新策略。
- 飞书本轮采用整批至少一次：第二页失败时，重试可能重复第一页；重启仍使用现有 24 小时回看。持久化 outbox 和按页确认属于后续独立设计。

## 质量与文档欠账

- 本轮已同步 `CONTEXT.md` 的 FTS5、已读状态、每日简报、飞书、缓存语义及实际表名，并补充 CI 与测试环境隔离。
- HTTP 请求与后台调度仍使用各自的入口；本轮缓存防重覆盖 HTTP 同键、调度防重覆盖调度器同路径，不承诺两者同时触发时只发起一次上游请求。
- 离线存储仍按挂载路径查询。修改一个挂载的来源后，如果新来源失败，可能返回该路径的旧来源文章；若要求彻底隔离，应给持久化引入来源身份并设计迁移。
- `countLogsToday/countErrorsToday` 用本地日期文本比较 UTC 时间戳，需改成明确时区下的日界限。
- 未对全部上游源逐个发起真实请求，未做大数据压测、浏览器视觉验收或依赖漏洞扫描。版本升级需依据官方发布说明与独立回归，不能仅凭版本号断言存在漏洞。
