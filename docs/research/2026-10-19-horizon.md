## 核心管线：README 与代码的对应

README 表述为“路由到 Profile → 分析、筛选、去重 → 生成区块 → 分组日报”。实际 CLI 管线更细：抓取时间窗 → 同 URL/相同请求 Profile 合并 → Profile 解析及评分 → Profile 阈值过滤 → Profile 内语义去重 → 对 X 候选补讨论及可能重评分 → 重新应用阈值 → 类别上限与总量上限 → 对入选项生成内容区块 → 逐语言确定性 Markdown 渲染、落盘和分发。入口为 `run`、`select_digest_items`、`filter_items`；应迁移阶段边界，不必移植整块 Python orchestrator。[管线源码](https://github.com/Thysrael/Horizon/blob/8f5446bf45c2d7763d17423d97d17906add85da1/src/orchestrator.py)

### Profile

- Profile 是“匹配依据 + 评分提示词 + 内容采样参数 + 展示区块/工具许可”，不是来源类别。定义由 `profile.json` 和 `match.md`、`analysis.md`、`enrichment.md` 组成。注册时读取文件、校验 ID、默认 Profile、引用、重复区块及提示词路径不能越出 Profile 目录；未知字段禁止。每个区块只有 `section` 类型，可标记 `optional`、`primary`；最多一个 primary，且 primary 必须必选。[Profile schema 与加载器](https://github.com/Thysrael/Horizon/blob/8f5446bf45c2d7763d17423d97d17906add85da1/src/processing/profiles.py)
- 来源可以指定单个 Profile、`auto` 或候选 Profile 列表。单个显式值直接使用，不花分类模型调用；auto 在全部 Profile 匹配；列表在限定集合匹配。最终每条内容只有一个有效 Profile。AI 匹配输出 `profile/confidence/reason`；失败降级默认 Profile，若默认不在候选中则用首项，置信度为 0。[分类器](https://github.com/Thysrael/Horizon/blob/8f5446bf45c2d7763d17423d97d17906add85da1/src/ai/classifier.py)
- 内置目录实际有 `tech-news`、`tech-blog`、`ai-creator`、`finance-news` 四套；README 介绍表仅举前三个。以科技新闻为例，区块为 summary、background、可选 impact、可选 community_discussion。[科技 Profile 示例](https://github.com/Thysrael/Horizon/blob/8f5446bf45c2d7763d17423d97d17906add85da1/profiles/tech-news/profile.json)、[金融 Profile 示例](https://github.com/Thysrael/Horizon/blob/8f5446bf45c2d7763d17423d97d17906add85da1/profiles/finance-news/profile.json)

### 评分和筛选

- 首轮模型结构化输出 `score/reason/summary/tags`，分数限定有限值 0–10。Profile 各自决定评分准则：科技新闻看及时性、突破与影响；技术长文看可迁移知识、证据与工程深度。不能把不同 Profile 分数解释成经校准的客观共同尺度。[结果模型](https://github.com/Thysrael/Horizon/blob/8f5446bf45c2d7763d17423d97d17906add85da1/src/models.py)、[新闻评分](https://github.com/Thysrael/Horizon/blob/8f5446bf45c2d7763d17423d97d17906add85da1/profiles/tech-news/analysis.md)、[长文评分](https://github.com/Thysrael/Horizon/blob/8f5446bf45c2d7763d17423d97d17906add85da1/profiles/tech-blog/analysis.md)
- 模型输入采用 Profile 控制的正文采样，并可带社区评论与互动数据。解析/契约失败后修复调用一次，仍失败标记 `score=null` 和失败原因。[分析器](https://github.com/Thysrael/Horizon/blob/8f5446bf45c2d7763d17423d97d17906add85da1/src/ai/analyzer.py)
- 运行偏好与 Profile 内容定义分开：`processing.profile_settings[id].threshold` 和 `topic_dedup`；阈值采用 `>=`。注意源码 `passes_profile_filter` 在未配置阈值时会接受已有 analysis，即便 score 为 null。迁移时应明确失败状态与资格判断，避免把该兼容行为当成必需特性。[配置模型](https://github.com/Thysrael/Horizon/blob/8f5446bf45c2d7763d17423d97d17906add85da1/src/models.py)、[筛选实现](https://github.com/Thysrael/Horizon/blob/8f5446bf45c2d7763d17423d97d17906add85da1/src/orchestrator.py)

### 两类去重

- 第一层在分析前按保守 URL key **与请求 Profile** 合并：scheme/host 小写、去默认端口、去末尾斜杠、忽略 fragment、去 utm 等追踪参数；保留业务 query 和其原有顺序；http 与 https 不合并。相同 URL 的不同显式 Profile/候选列表不会在此合并。选择正文最丰富项为主项，补充来源元数据与其他内容。[URL 规范化与合并](https://github.com/Thysrael/Horizon/blob/8f5446bf45c2d7763d17423d97d17906add85da1/src/orchestrator.py)
- 第二层只在**最终 Profile 内、阈值之后**执行：按分数降序，将标题、标签、短摘要交给模型分组。提示词要求组首为保留项，其余合并内容后从本轮候选剔除。调用或解析失败则保留所有候选；不是数据库永久删除，也不是跨日事件聚类。一个 Profile 的所有候选放一次请求，规模扩大时存在上下文与费用风险。[语义去重实现](https://github.com/Thysrael/Horizon/blob/8f5446bf45c2d7763d17423d97d17906add85da1/src/orchestrator.py)、[去重提示词](https://github.com/Thysrael/Horizon/blob/8f5446bf45c2d7763d17423d97d17906add85da1/src/ai/prompting/deduplication.py)

### 日报与配额

- 类别份额由 `metadata.category` 映射 `digest.category_groups`，与 Profile 分组独立。按分数降序贪心纳入，类别达到 limit 后跳过，再裁剪 `max_items`；类别同时属于多组时取配置中的第一组；未映射项进入 default_group。它是**上限约束**，没有每类最低保底、比例分配或不足补位。[配额算法](https://github.com/Thysrael/Horizon/blob/8f5446bf45c2d7763d17423d97d17906add85da1/src/orchestrator.py)
- 最后日报由 `DailySummarizer` 程序化生成 Markdown，按 Profile 分组及 profile_order 排序，组内沿用分数顺序；不是再让模型重新撰写整份日报。模板带来源、分数、区块、标签、参考链接，空结果有明确文案。[日报渲染器](https://github.com/Thysrael/Horizon/blob/8f5446bf45c2d7763d17423d97d17906add85da1/src/ai/summarizer.py)

## 对迁移计划的建议与风险

以下是基于上面源码的设计推论，不是 Horizon 提供的保证：

1. 迁移行为和配置语义，保持 Java 单体、SQLite、现有抓取与 AI 队列，不嵌入 Python 子进程。处理结果、日报快照、原文应分开，去重不能删除用户收藏或阅读状态。
2. Profile 与来源 category 分离；显式 Profile 优先完成，auto 分类可以后置。先内置科技新闻与技术长文两种规则即可验证不同读法。
3. 对分析缓存记录内容摘要、模型与提示词/Profile 版本；Profile 改动需要可控重算。Horizon 的可变内存 processing 不能直接替代本项目持久化作业状态。
4. 无分数、非法 JSON、模型超时应标记失败并可重试，不赋零分混同低价值，不因未设阈值混入日报。
5. URL 去重与语义去重分别验收。语义分组需验证 ID、重复成员、重叠组与主项选择，失败保留原候选；限制批次或候选数控制上下文。记录主项和所有来源，便于用户追溯。
6. 日报固定时区、时间窗、输入集合、Profile/模型版本和语言；重试或刷新不应让历史阅读页随当前配置悄悄变化。初期先本地页面及 Markdown，复用现有飞书时使用日报快照。
7. 模型打分主观且跨 Profile 不可天然比较；准备一组用户认可的文章样例校准阈值，量化每轮候选、成功分析、阈值剔除、去重合并、配额剔除、最终条目和模型耗时。
