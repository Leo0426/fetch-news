# 精选日报

精选日报（代码中称为 radar）让 AI 把某一天保存的文章逐篇打分、合并同一事件的报道、按上限挑选，再为入选文章生成中文解读，最终形成一份不可变的日报。原始 RSS、阅读器、收藏、AI 摘要和飞书推送都不受影响。

## 启用

精选日报是内置能力，没有单独的配置：在后台「AI 设置」中启用 AI 即可。之后：

- 每天 08:00（北京时间）自动为前一天的文章生成日报。
- 在 `/reader/radar` 选择日期，可以随时手动生成。
- 关闭 AI 后不再生成新日报，已有日报仍可阅读和下载。

内置规则：所有来源都使用 `tech-news` Profile 评分，达到 7 分才能入选，每份日报最多 20 条，最多分析 200 篇候选，单份日报最多调用模型 500 次、运行 60 分钟。Profile 的提示词位于 `src/main/resources/radar/profiles/tech-news/`，修改后需要重新构建。

每份日报都要逐篇调用模型，一天几十到几百次。使用付费 API 时请留意用量。

## 日报语义

- 文章按**首次发现时间**归入北京时间的自然日，不按发布日期。晚到的文章属于首次发现那天；不伪造发布时间。
- 生成时保存文章标题、正文、来源、规则和模型身份的快照，之后的抓取不会改变旧日报。同一天再次生成会保存为新版本。
- 只分析最新的 200 篇候选，页面显示总数和未覆盖的数量。上限只限制最多入选多少条，不会用低分内容补满。
- 分数范围 0–10。模型返回非法 JSON、缺字段或调用失败，都记为分析失败，不当作低分处理。
- 同一事件的多篇报道合并为一条，保留全部原文链接。已知发布日期不同或版本号明确不同的报道不合并，其余由模型保守判断；宁可留下少量重复，也不误合并。
- 只为入选文章生成解读。正文不足时会提取全文；某一段生成失败时保留其他段落并显示原因。生成内容均标为 AI 内容，不能代替原文核验。
- `success` 是完整结果；`partial` 表示超出上限、部分分析失败、预算耗尽或去重降级。没有文章达到阈值也是合法结果。
- 同一天优先显示最新的成功版本，没有成功版本时显示最新的部分版本。新一次生成失败不会覆盖原有的成功日报。下载链接绑定具体版本。

## 定时、恢复与预算

定时任务每分钟检查一次，错过触发时间时只补最近一个到期的窗口。重复检查和重启使用同一个幂等键，不会重复生成；规则或模型变化时会生成新版本。日报任务不会主动刷新订阅，抓取仍由原来的调度器负责。

生成过程中关闭 AI 或切换模型，任务会在下一步之前暂停。恢复原模型后在日报页点击「恢复任务」，或者重新生成一个新版本。应用重启会把进行中的任务标记为暂停，保留已完成的结果，不会自动反复重试。

调用次数在请求前记录，正文提取所需的模型调用也计入预算。崩溃恢复时，未结算的运行时间（包括停机期间）会保守地计入预算，防止通过反复重启绕过上限。预算耗尽会产生一份明确标记的部分日报。

目前只支持单个应用实例。升级前请停机备份 SQLite 数据库，不要直接复制正在写入的数据库文件。

## Hacker News 讨论

在日报的每条内容下展开「Hacker News」可以查看已缓存的讨论，点击获取后才会访问上游。系统会核对讨论条目的原文 URL，避免把另一篇文章的评论配到当前内容上。

每次只读取故事本身和最多 10 条顶层评论，过滤已删除或屏蔽的内容，保留作者和原评论链接。社区观点和其中的参考链接不作为已核实事实。结果单独缓存，不修改日报，也不参与评分；30 分钟内对同一篇文章的请求复用同一个任务。

## API

| 方法与路径 | 行为 |
|---|---|
| GET `/reader/radar?date=YYYY-MM-DD` | 只读日报页 |
| POST `/reader/radar/runs` | 表单 `date`、`zoneId`、`requestKey`，返回 202 和任务状态（仅管理员） |
| GET `/reader/radar/runs/{runId}` | 任务状态、阶段与调用次数 |
| POST `/reader/radar/runs/{runId}/resume` | 恢复暂停的任务（仅管理员） |
| GET `/reader/radar/runs/{runId}/markdown` | 下载指定版本的 Markdown |

同一 `requestKey` 重试不会产生第二个任务。AI 未启用时返回 409，存储不可用返回 503，任务或日报不存在返回 404。

## 验证边界

自动化测试使用临时 SQLite 和本地假模型，覆盖真实 HTTP、持久化、阈值、上限、故障、重启和页面，不访问真实订阅或真实模型。**尚未用真实模型做过质量评估**；日常使用前建议先手动生成几份，检查打分和事件合并的效果。

接口依据：[Hacker News 官方 API](https://github.com/HackerNews/API)。
